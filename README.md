# 鲁班 · 自动驾驶研发项目管理系统

> 内部研发工具 · 当前版本 Phase 3 · 2026年5月

---

## 一句话定义

**鲁班是专为自动驾驶研发团队设计的版本全生命周期管理平台**，覆盖从需求入口到版本交付的完整研发流水线，替代分散在多个 Excel/飞书表格中的版本跟踪工作。

---

## 我们在解决什么问题

### 现状痛点

自动驾驶软件研发具有以下特殊性，使通用项目管理工具难以适配：

| 痛点 | 具体表现 |
|------|----------|
| **流水线复杂** | 每个版本经历需求→开发→测试→交付四大阶段，每阶段有多个并行子节点（SIL/HIL/路测等），状态追踪极难 |
| **质量门禁缺失** | 阶段间跨越（如开发→测试）需要审核+证明材料，现在靠人工提醒，经常漏掉 |
| **延期感知滞后** | 只有在 deadline 到了才发现某个版本已经延期，没有主动预警 |
| **信息分散** | 版本进展散落在群聊、飞书文档、个人备忘录，领导无法一眼看全局 |
| **责任不清晰** | 哪个版本由谁负责、卡在哪个节点、是谁的原因，没有系统记录 |

## 系统已实现的核心能力

### 1. 版本看板 — 全局一张表

- 所有在研版本一屏呈现，按版本号、项目名、研发模块、责任人、优先级分列
- 每个版本的五大流水线节点（需求/生成/开发/测试/交付）在同一行展开，当前子阶段、计划时间、状态一目了然
- **整体状态**自动计算：完成 / 正常 / 风险 / 延期，不需要人工维护
- 告警横幅：顶部红色横条自动聚合所有风险版本，每次打开系统即知晓需要关注什么

### 2. 流水线进度 — 每个版本都是一条泳道

- 版本详情侧边抽屉，横向步骤条展示五大节点实时进度
- 每个节点下：计划时间 / 实际时间 / 当前子阶段（如"SIL集成测试"）
- 节点完成后自动推进，当前活跃节点高亮

### 3. 阶段门禁审核 — 质量关卡数字化

- 开发→测试、测试→交付两个跨阶段节点设有审核门禁
- 责任人提交时须上传证明材料（文档链接、截图、CommitID）
- 审核人在系统内一键通过/驳回，驳回需填写理由，全程留痕
- 打回历史在版本详情可追溯，永久记录

### 4. 跟进日志 — 每日进展有据可查

- 每个版本独立日志区，支持按日期倒序查看所有历史记录
- 支持 Ctrl+V 直接粘贴截图（Snipaste 等工具截图后直接粘贴）
- 图片自动压缩（WebP 格式，最大1200px，80%质量），不占服务器空间

### 5. 多维筛选 — 快速定位关心的版本

- **研发模块筛选**：只看感知/规控/定位/系统某一模块的版本
- **帽子（Tag）筛选**：自定义分类标签，一键过滤
- **优先级筛选**：聚焦高优先级 / T0 版本
- **阶段 Tab**：点击"需求/开发/测试/交付"，只看当前正在该阶段推进的版本
- **里程碑筛选**：按版本冲刺节点（如 V615、V630）筛选，支持归档历史里程碑

### 6. 字典化配置 — 完全适配业务语言

- 研发模块、优先级、节点状态、阶段模板、人员均可在系统设置内自定义
- 无需改代码，PM/管理员可自行维护字典，系统自动生效

### 7. 用户登录与权限

- 用户名+密码登录，httpOnly Cookie 会话
- 操作自动带入当前登录人身份，日志、审核、打回均有操作人记录

## 技术实现简介

| 层级 | 技术选型 | 理由 |
|------|----------|------|
| 前端框架 | Next.js 16 + TypeScript | 服务端渲染，SEO友好，单仓库前后端 |
| 数据库 | SQLite + Prisma ORM | 轻量部署，无需独立数据库服务，迁移方便 |
| 样式 | Tailwind CSS | 快速开发，主题变量统一管理 |
| 图片处理 | sharp | 服务端压缩，自动转 WebP |
| 部署 | 阿里云 ECS 2c4g + PM2 | 低成本，稳定，5分钟可迁移 |

**代码规模**：约 8,000 行（含 schema、API、组件），纯内部自研，无外部 SaaS 依赖，数据完全自主可控。

## 投入产出估算

**现状替代成本**：
- 现有方式：每个PM每周约 3–4 小时整理版本状态表，同步给领导；一旦信息错漏，排查成本极高
- 引入鲁班后：版本状态实时更新，领导随时自助查看，**每周节省跨角色同步会议 1–2 次**
- 对比市面同类工具（Jira/Monday/禅道定制版）：**定制化程度更高，零 SaaS 订阅费用，数据完全自主可控**
